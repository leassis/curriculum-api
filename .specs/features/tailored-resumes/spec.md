# Tailored Resumes Specification

**Approved**: pending

**Depends on**: `foundation` merged (AD-003). Owns: `src/admin/resumes.tsx`, `src/admin/print.tsx`, `src/services/resume.service.ts`, `src/repositories/resume.repository.ts`, `src/lib/markdown.ts`, their tests.

## Problem Statement

For each application the Owner wants a Career Body tailored to a Job Description. It is generated by the tailor model from the Master CV, edited by hand, and printed as an ATS-friendly A4 resume with the Owner's real contact data. The LLM must only ever see the Career Body and the Job Description. Header and body are joined on the server, without an LLM.

## Goals

- [ ] Paste a Job Description → generate → edit → print to PDF with real contact data.
- [ ] The tailor model never receives a Personal Info Field value.
- [ ] LLM output is never injected as raw HTML.

## Out of Scope

| Feature | Reason |
| ------- | ------ |
| Server-side PDF generation | §5.5: browser "Save as PDF" only |
| Streaming generation into the textarea (SSE) | §7 marks it optional; non-streaming `generateText` |
| Linking a resume to a recruiter chat | `recruiter-chat` track owns the chat form and context |
| Version history of a resume | Not in source |

## User Stories

### P1: Create, list and delete resumes ⭐ MVP

**User Story**: As the Owner, I want to create a resume from a title, company and Job Description, see all resumes, and delete old ones.

**Why P1**: Generation and print need a resume to exist.

**Acceptance Criteria**:

1. WHEN `GET /admin/resumes` is requested THEN the app SHALL list resumes newest first with title, company, model used and updated date, each linking to `/admin/resumes/:id`.
2. WHEN no resume exists THEN the list SHALL show the text "No tailored resumes yet".
3. WHEN `POST /admin/resumes` receives a non-empty title and Job Description and an optional company THEN the app SHALL create a resume with empty content and answer 303 to `/admin/resumes/:id`.
4. IF title or Job Description is empty THEN the app SHALL answer 400 with a fragment naming the field and SHALL not create the resume.
5. WHEN `DELETE /admin/resumes/:id` is confirmed via `hx-confirm` "Delete <title>?" THEN the app SHALL delete it and remove its row from the list.
6. IF `:id` does not exist or is not a UUID THEN every `/admin/resumes/:id*` route SHALL answer 404.

**Independent Test**: Create → redirected to the edit page; list shows it; delete → gone.

---

### P1: Generate with the tailor model ⭐ MVP

**User Story**: As the Owner, I want to generate a tailored Career Body for the Job Description so that I start from a good draft.

**Why P1**: Core of the feature.

**Acceptance Criteria**:

1. WHEN `POST /admin/resumes/:id/generate` is requested THEN the app SHALL call `llmService.generate` with area `tailor`, system prompt = `tailorSystemPrompt`, input = Master CV + the resume's Job Description, and `maxOutputTokens = 4000`.
2. WHEN generation succeeds THEN the app SHALL save the markdown to `content`, save the model ID to `model`, and return the editor fragment with the new content.
3. WHILE generation runs, the Generate button SHALL show a loading indicator via `hx-indicator` and be disabled.
4. IF `llmService.generate` throws `LlmUnavailableError` THEN the app SHALL answer 502 with the fragment text "Generation failed, try again" and SHALL leave `content` unchanged.
5. IF the Master CV is empty THEN the app SHALL answer 400 with the text "Fill the master CV first" and SHALL not call the LLM.
6. WHEN any generate test runs THEN the recording mock model SHALL have received no Personal Info Field value and no `profile.fullName`.

**Independent Test**: Mock returns "# Body" → content saved, model saved; mock fails → 502, content unchanged.

---

### P1: Edit and preview ⭐ MVP

**User Story**: As the Owner, I want to edit the markdown, pick the header fields, and see a safe preview so that the resume says exactly what I want.

**Why P1**: LLM output always needs a human pass.

**Acceptance Criteria**:

1. WHEN `GET /admin/resumes/:id` is requested THEN the app SHALL render title, company, Job Description, a markdown textarea with `content`, one checkbox per Personal Info Field for `headerFields`, and buttons Generate, Save, Print, Download .md.
2. WHEN `POST /admin/resumes/:id/preview` receives markdown THEN the app SHALL return sanitized HTML of it.
3. IF the markdown contains raw HTML (e.g. `<script>`, `<img onerror>`) THEN the preview SHALL contain no element or attribute from it outside the allowlist (`h1-h6, p, ul, ol, li, strong, em, a[href http/https/mailto], code, pre, blockquote, hr, br`).
4. WHEN `PUT /admin/resumes/:id` receives content and header fields THEN the app SHALL save them and return the text "Saved".
5. IF the content contains a Personal Info Field value THEN the save SHALL answer 400 with "Your <label> is in the body — keep contact data in Personal info" and SHALL not save.

**Independent Test**: Preview `<script>alert(1)</script>**x**` → `<strong>x</strong>` and no `<script>`.

---

### P1: Print and download ⭐ MVP

**User Story**: As the Owner, I want an A4, ATS-friendly print view and a markdown download of each resume and of the Master CV so that I can send a real resume with my contact data.

**Why P1**: Roadmap Phase 4 "done when": print to PDF with real contact data.

**Acceptance Criteria**:

1. WHEN `GET /admin/resumes/:id/print` is requested THEN the app SHALL render `h1` = `profile.fullName`, then the Personal Info Fields in `headerFields` (all fields when NULL) ordered by `sortOrder`, then the sanitized HTML of `content`.
2. WHEN `GET /admin/profile/print` is requested THEN the app SHALL render the same page with all Personal Info Fields and the Master CV.
3. Both print routes SHALL answer with `Cache-Control: no-store` and `X-Robots-Tag: noindex`, and SHALL not call the LLM.
4. The print stylesheet SHALL set `@page { size: A4; margin: 16mm 18mm; }`, or `size: Letter` WHERE the Settings Override `print.pageSize` is `Letter`.
5. The print page SHALL use no `<table>` for layout, no images of text, and a "Print / Save as PDF" button calling `window.print()` that is hidden in print media.
6. IF the PII Guard finds a Personal Info Field value inside the body THEN the print page SHALL show a screen-only warning banner naming the field label.
7. WHEN `GET /admin/resumes/:id/download.md` is requested THEN the app SHALL answer `text/markdown; charset=utf-8` with `Content-Disposition: attachment; filename="<slug>.md"` containing `# <fullName>`, one line per header field `label: value`, a blank line, then `content`.

**Independent Test**: `headerFields = [EMAIL]` with `EMAIL`, `PHONE` defined → print shows email, not phone; download contains `Email: …`.

---

## Edge Cases

- WHEN a Personal Info Field listed in `headerFields` is deleted THEN print and download SHALL skip it without error.
- WHEN `content` is empty THEN print SHALL render the header and the text "This resume is empty".
- WHEN the resume is deleted while linked to a recruiter chat THEN the delete SHALL succeed (FK `on delete set null`, foundation FND-06).
