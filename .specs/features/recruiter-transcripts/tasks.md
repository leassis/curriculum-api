## Design decisions (inline)

- AD-003 exception (orchestrator): `src/db/schema.ts` and `drizzle/` (generated by `drizzle-kit generate`) change. `container.ts` and `app.ts` stay untouched: the methods live on the existing `RecruiterChatRepo` / `RecruiterChatService`.
- Table `recruiter_chat_messages`: `id uuid`, `chat_id uuid not null references recruiter_chats(id) on delete cascade`, `seq bigint generated always as identity`, `role text check in ('user','assistant')`, `content text not null`, `created_at timestamptz default now()`; index on `(chat_id, seq)`.
- Repo: `addMessages(chatId, [{role, content}])` is one multi-row `INSERT` (atomic, identity order = array order); `messages(chatId)` ordered by `seq`.
- Service `ask`: after the stream is obtained, the redacted last user message is computed with `redactPii` over `personalInfo.allValues()`. The returned stream is piped through a `TransformStream` that collects chunks and, in `flush` (normal completion only), calls `addMessages` with the redacted pair. An error or cancel never reaches `flush`, so nothing is stored. A storing failure is caught and logged; the stream still closes.
- `RecruiterChatService.transcript(id)` returns `{ chat, messages }` (NotFound for unknown or malformed id). The admin page imports only the service.
- Existing contract tests that count tables or migrations ("seven tables", "exactly one migration") are updated to the new facts; no assertion is weakened otherwise.
- Admin page `src/admin/messages.tsx`, a router mounted next to `chatsRouter`; escaping comes from JSX; no script on the page except the layout's `src` scripts.
